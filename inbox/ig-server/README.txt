СЕРВЕРНЫЙ ПУБЛИКАТОР REELS ДЛЯ INSTAGRAM
========================================

ЗАЧЕМ
Приложение «Диалог Деск» публикует по расписанию, пока включён компьютер и есть интернет.
Этот публикатор живёт на сервере, который не выключается. В нужный час он сам берёт следующий
ролик из папки, кладёт его на GitHub (быстрым серверным каналом), просит Instagram забрать
оттуда, ждёт обработки и публикует. Интернет вашего компьютера в этой цепочке не участвует.

Расписание и правила те же, что в приложении: слот по дню недели и времени, окно опоздания
180 минут, не больше 3 публикаций в сутки, пауза между выходами 90 минут, после неудачи повтор
через 25 минут (до 3 попыток в день). Ролики идут по номерам: 01_..., 02_..., 10_...;
подпись лежит рядом в файле с тем же именем и расширением .txt.

ЧТО НУЖНО
- Python 3.8 или новее (у вас он уже стоит для других сервисов). Ничего доустанавливать не надо.
- Токен Instagram для аккаунта (тот же, что в приложении).
- Токен GitHub с правом записи в репозиторий ig-media (Contents: Read and write).

УСТАНОВКА (на сервере, PowerShell от администратора)
1. Папка C:\ig-publisher с файлами ig_publisher.py, config.example.json, install.ps1.
2. Ролики и подписи должны лежать в C:\ig-publisher\videos\saudiago (01_bezviz.mp4 + 01_bezviz.txt, ...).
   Если слать с компьютера долго, положите файлы в папку inbox репозитория на GitHub (быстрым каналом) и
   выполните на сервере: python C:\ig-publisher\ig_publisher.py fetch-inbox saudiago
   Сервер скачает всё сам; уже скачанное пропускает, оборванную загрузку можно просто повторить.
3. powershell -ExecutionPolicy Bypass -File C:\ig-publisher\install.ps1
   Первый запуск создаст config.json и остановится: откройте его, вставьте токены вместо слов
   ВСТАВЬТЕ…, сохраните в UTF-8 и запустите install.ps1 ещё раз. Он проверит доступы (ничего не
   публикуя) и поставит задачу «IgPublisher» в Планировщик: раз в минуту, без окна, от SYSTEM.
4. В приложении «Диалог Деск» ВЫКЛЮЧИТЕ расписание Instagram для этого аккаунта (иначе
   публиковать будут и приложение, и сервер). Страховка от дубля есть: сервер не выкладывает
   ролик, подпись которого уже есть в ленте, но полагаться только на неё не стоит.

Установка в середине дня не «догоняет» слоты, время которых уже прошло: первым выйдет ближайший.

КОМАНДЫ (из папки C:\ig-publisher)
  python ig_publisher.py status                     очередь, ближайшие выходы, последние попытки
  python ig_publisher.py check                      проверить доступность Instagram/GitHub, токены, ролик
  python ig_publisher.py publish-now saudiago --yes выложить следующий ролик СЕЙЧАС (настоящая публикация)
  python ig_publisher.py mark-published 01_bezviz.mp4 --account saudiago   считать ролик вышедшим
  python ig_publisher.py forget 01_bezviz.mp4 --account saudiago           вернуть ролик в очередь
  python ig_publisher.py set-proxy                  записать адрес прокси для Instagram в config.json
  python ig_publisher.py fetch-inbox saudiago       скачать ролики и подписи с GitHub (папка inbox) в папку аккаунта
Журнал: publisher.log. Состояние: state.json (что вышло, попытки, токен после продления).

ЕСЛИ INSTAGRAM ИЗ РОССИИ НЕ ДОСТУПЕН
Команда check покажет «НЕ ДОСТУПЕН» у Instagram API. Тогда нужен прокси ТОЛЬКО для Instagram:
выполните python ig_publisher.py set-proxy и вставьте адрес (или впишите его в config.json в поле "proxy") в виде http://логин:пароль@адрес:порт или socks5://логин:пароль@адрес:порт.
Через прокси пойдут только короткие запросы к graph.instagram.com (токен, контейнер, публикация);
ролики идут на GitHub напрямую. Соединение с Instagram остаётся зашифрованным насквозь:
прокси видит только адрес, но не токен. Нужен прокси не из России.

ЕСЛИ СВЯЗЬ ОБОРВАЛАСЬ НА ПОСЛЕДНЕМ ШАГЕ
Публикацию контейнера повторять вслепую нельзя: пост мог выйти. В этом случае аккаунт ставится
на паузу на 30 минут, потом сервер сверяет ленту: ролик там — отмечает вышедшим; нет — выкладывает заново.

ТОКЕНЫ
Токен Instagram сервер продлевает сам раз в 30 дней (хранит в state.json). Если вы замените токен
в config.json, главным станет новый. Токен GitHub выпустите долгоживущим: когда он истечёт,
сервер напишет «GitHub не принял токен» в журнал (и в Telegram, если он подключён).

УВЕДОМЛЕНИЯ В TELEGRAM (необязательно)
В config.json: "notify": {"telegram_bot_token": "...", "telegram_chat_id": "..."}. Придёт сообщение
о каждой публикации, ошибке и неясном исходе.

ДРУГОЙ АККАУНТ
В config.json скопируйте блок аккаунта в "accounts", поменяйте name, token, videos_dir, github_dir
(папка в репозитории: cards, saudia, isceleniye, mysli) и slots.

УДАЛЕНИЕ
powershell -ExecutionPolicy Bypass -File C:\ig-publisher\install.ps1 -Remove
